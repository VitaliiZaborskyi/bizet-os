# BIZET OS 1.0 — Spec ↔ Code gaps (Build 0.6)

Этот список фиксирует расхождения первого тестируемого прототипа со спецификацией v0.9. Они **не исправлены мебельной логикой от разработчика** и должны закрываться только подтверждёнными правилами BIZET.

1. **Вертикальная система нижнего ряда (OQ-03/OQ-04).** Точная высота цоколя, корпуса и рабочей поверхности не утверждена. 2.5D-визуализатор использует только схематичную высоту нижнего ряда и явно так её маркирует.
2. **Верхние модули не генерируются Module Engine как полноценный ряд.** Спецификация содержит правила верхних шкафов, сушилки, антресолей и потолочного примыкания, но Build 0.6 визуализирует основной горизонтальный layout пилота. Ceiling Engine пока влияет на warnings/metadata, а не строит полный верхний ряд.
3. **Открытое завершение кухни не имеет отдельного выбранного типа в ProjectInput.** Фасадная боковина до пола / панель из материала столешницы / завершение над цоколем описаны спецификацией, но пользовательский enum ещё не утверждён.
4. **Точная траектория открывания фасадов/ручек не моделируется геометрически.** Filler Engine применяет утверждённые правила 18/40 мм и G-образного филлера для HANDLE, но collision envelope двери/ручки отсутствует.
5. **Проверка электровывода относительно реального 3D-габарита техники не реализована.** Compatibility Engine проверяет наличие обязательного вывода и хранит policy допустимой зоны; точный XYZ-контроль «не за корпусом прибора» требует утверждённой вертикальной геометрии и placed appliance envelopes.
6. **“Шаговая доступность” и функциональный маршрут пользователя проверяются эвристикой размещения, но не отдельной измеримой метрикой.** Нет утверждённых численных критериев расстояния.
7. **Переходы визуальных линий с дверями/окнами/проёмами не валидируются автоматически.** Architectural guides есть в концепции спецификации, но нет утверждённой схемы приоритетов/весов для кода.
8. **Маршрут воздуховода встроенной вытяжки не рассчитывается.** Как и требует v1.0, такой случай получает Human Review; автоматической геометрии канала нет.
9. **Газовая труба не трассируется.** При газовом сценарии, влияющем на мебель, Build 0.6 передаёт Human Review.
10. **Минимальная ширина лотка для приборов OQ-01 не финализирована.** В ruleset хранится пилотная конфигурируемая константа 400 мм, отмеченная в rule trace.
11. **Preferred widths внутри сетки 50 мм не утверждены как мебельное правило.** Генератор использует ограниченную пилотную эвристику поиска кандидатов; standard/nonstandard определяется только кратностью 50 мм.
12. **Номер заявки имеет правильный формат NNN.MM.YY и стабилен в пределах UI-сессии, но monthly counter хранится in-memory процесса.** Для многопользовательского production нужен транзакционный persistent counter/DB; это техническая, не мебельная задача.
13. **3D Scan ingestion отсутствует.** Manual Room Input реализован; scan adapter сознательно отложен согласно prototype plan.
14. **Экспорт результата реализован через browser Print/PDF, а не отдельный серверный PDF renderer.** На result screen и печати присутствует BIZET watermark.
15. **Материалы/цвет/ценообразование/фотореалистичный render/CNC отсутствуют сознательно — Out of Scope v1.0.**

## Что уже проверяется Final Validation
- точная арифметика общей длины;
- горизонтальные коллизии layout items;
- наличие выбранной pilot-scope техники в layout;
- непосредственная смежность ПММ и мойки;
- STOP/Human Review из Compatibility Engine;
- wall deviation Human Review из Room/Filler Engine;
- warnings нестандартной ширины и confidence/source входных данных.
